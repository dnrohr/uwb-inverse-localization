# M6: Multipath simulation and robust estimation

M6 extends the saved M4/M5 range experiment with reproducible contamination and robust range fitting. Its versioned run schema is `6.0`. The source M5 experiment, contaminated observations, per-source contamination records, estimator options, every attempted start, and the resulting diagnostics are saved together. Synthetic clean ranges and labels are evaluation references; the fitting function receives the estimator observations, their declared uncertainties and timing, and any surveyed beacon map declared by the experiment.

For acceptance evidence and current implementation checks, see [M6_ACCEPTANCE.md](M6_ACCEPTANCE.md). This document describes the model and controls; it does not assert an acceptance result.

## Contamination generation

M6 first generates the configured M5 experiment, including its path, beacon geometry, acquisition schedule, timestamp assumptions, and white range noise. It then applies the following stages in order to each acquired source range:

1. Add a fixed per-beacon offset in metres.
2. Add a stationary AR(1) noise value for that beacon and estimator cycle.
3. Add a positive NLOS bias when the beacon-cycle is labeled contaminated.
4. Quantize the resulting range to the configured step using nearest-even rounding.
5. Apply independent packet dropout.

The contamination generator uses a separate unsigned 32-bit seed exposed in the M6 controls and restored from saved runs. A new numerical experiment defaults to `(measurement_seed + 606) mod 2^32`; the UI starts at 613. In sweeps each cell uses `(normalized_base_contamination_seed + measurement_seed) mod 2^32`, and the start stream uses `(base_initialization_seed + measurement_seed) mod 2^32`. Both effective seeds are saved. NumPy `default_rng` and `SeedSequence(seed).spawn(3)` create independent random streams for NLOS onsets, AR(1) innovations, and dropout. The generated `contamination_reference.records` retain a record for every source ping, including pings later dropped. Each record separates the clean range, original white-noise contribution, offset, correlated-noise contribution, positive NLOS bias, quantization error, resulting range, NLOS label, dropout label, and source/retained indices.

NLOS prevalence is the independent Bernoulli probability of an onset at each eligible beacon/cycle, not the final fraction of affected ranges. Each onset marks that cycle and the following `burst_duration_cycles - 1` cycles for the beacon. Overlapping bursts merge. A duration of one cycle gives the isolated-outlier case; isolated outliers and NLOS therefore share the same fixed positive-bias model. The magnitude must be positive, even when prevalence is zero. Affected beacon IDs may be selected explicitly; the default is all configured beacons.

Per-beacon offsets are fixed values in metres, one per beacon. Correlated noise uses an independent stationary AR(1) process for each beacon on the complete cycle grid, including cycles where acquisition has no ping. Its `correlated_noise_std_m` is the stationary standard deviation; `correlation` is between adjacent cycle indices, not elapsed seconds, and lies in `[-0.999, 0.999]`. Base M5 white noise remains additive. Quantization step and dropout probability are nonnegative metres and a probability in `[0, 1]`, respectively. Dropout occurs after the M5 acquisition schedule, so missing pings do not enter estimator decisions. M6 does not silently increase the assumed range uncertainty to account for contamination or quantization.

The UI lets a user select a clean baseline, NLOS, one-cycle isolated outliers, longer bursts, offsets, correlated noise, quantization, dropout, or combined sources. Unselected factors are set to zero in the generated contamination configuration. The standalone offset experiment uses the explicit offset vector. The `offset_m` benchmark factor sets the same offset on every beacon. The UI preserves seeds as paired data instances; a seed list is not counted as additional repetitions beyond those listed seeds.

## Estimators, scales, and decisions

The range residual is predicted range minus measured range. M6 divides each range residual by the original assumed range standard deviation before applying its loss. The separate motion and height prior residuals retain their M5 quadratic objectives and are not treated as measurements. M6 supports the M5 trust-region reflective solver with native bounds and the strict-interior exponential Levenberg–Marquardt parameterization, subject to M5's physical model and solver restrictions. Unsupported loss, solver, geometry, and option combinations are rejected explicitly.

Supported range losses are:

- **Gaussian:** ordinary least squares on normalized range residuals.
- **Huber:** quadratic near zero and linear in residual magnitude beyond its scale.
- **Soft L1:** smooth transition from quadratic to linear growth.
- **Cauchy:** logarithmic growth for large residuals.
- **Hard rejection:** a Gaussian pilot fit computes a mask at the configured residual threshold. M6 retains measurements whose absolute pilot residual in sigma units is less than or equal to the threshold, then performs one Gaussian fit initialized at the pilot geometry with the mask frozen. No contamination labels select the mask. A start fails if the mask retains no range measurements or violates the solver's residual-count requirements.

`loss_scale_sigma` is the robust-loss scale in units of the original assumed range sigma. `rejection_threshold_sigma` is the hard-rejection pilot threshold, also in sigma units. For continuous losses, `weight_decision_threshold` marks observations whose influence weight is strictly below that value. This is an inspection/evaluation rule; a flagged continuous-loss range remains in the objective when its weight is positive. Hard-rejection decisions are flagged when their frozen pilot weight is zero, which also means the range is excluded. The UI distinguishes flagged, downweighted and zero-weight rejected observations. It also displays the pilot residual for hard-rejection attempts when available.

Writing `r = (predicted - measured) / assumed_sigma` and `c = loss_scale_sigma`, the smooth range objective is `.5 * c^2 * sum(rho((r/c)^2))`, plus the unchanged quadratic motion and height prior objectives. The supported functions are `rho(z)=z` for Gaussian, `rho(z)=z` for `z<=1` and `2*sqrt(z)-1` otherwise for Huber, `rho(z)=2*(sqrt(1+z)-1)` for soft L1, and `rho(z)=log(1+z)` for Cauchy. Hard rejection instead uses a Gaussian objective over the frozen binary pilot mask. M6 implements each smooth range objective as a signed square-root transformed residual, keeping prior rows quadratic. For Huber, soft L1, and Cauchy, the diagnostic influence weight is `rho'(z)` with `z = (r / c)^2`. The effective retained-information matrix uses the square root of those weights. The separate positive-part robust-curvature diagnostic uses the positive part of the signed scalar curvature; it is a conditioning surrogate and excludes geometry second derivatives and priors.

Hard-rejection masks may differ across starts. The selected start prefers converged finite estimates and then the smallest final optimizer objective, but objective values under different masks are not a common-data quality score. Compare all-data residuals, geometric error, rejection metrics, retained information, convergence, and every attempt together. A lower residual after removing ranges alone is not evidence of improved localization.

## Diagnostics and interpretation

Each successful attempt saves signed residuals, normalized residuals, influence weights, threshold flags, hard-rejection decisions, and source indices. The source index connects a decision to its separate injected-reference record after fitting. Dropped pings have no estimator decision; they remain visible in the source records and are accounted for separately. NLOS precision, recall, and false-positive rate compare the declared injected NLOS labels with the decision rule after fitting. Other contamination factors, including offsets and quantization, are not NLOS labels. Dropped pings are excluded from rejection denominators, and a metric is undefined when its denominator is zero.

Coverage reports original, positive-weight retained, and flagged observation counts; effective influence-weight sums; and the same counts by beacon and estimator epoch. A positive-weight range is retained in the objective even when flagged. Missing pings due to dropout are outside these estimator counts and are not called rejected.

Information diagnostics are evaluated in the physical metre coordinates and selected canonical gauge, using the original range sigma and a shared column scale based on the median absolute original range (minimum one metre). The original measurement-only Jacobian and weighted measurement-only Jacobian are reported separately, with their singular spectra, rank tolerance, and condition diagnostics. The weighted matrix freezes the final influence weights; it is not the exact robust curvature. Hard rejection sets the weights to its frozen binary mask. A prior-augmented matrix adds motion and height prior rows and remains explicitly separate from measurement information. Priors are assumptions, not extra measurements.

The sweep summary derives a local weighted-spectrum information change as `1 - sum(s_retained^2) / sum(s_original^2)` from those common-scaled physical spectra. It is a first-order information diagnostic, not a proof of continuous ambiguity. Rank deficiency does not prove a continuous family of solutions; full local rank does not prove uniqueness. The robust-curvature spectrum is also reported separately and should not be conflated with either the frozen-weight matrix or prior-augmented information.

The estimator uses the assumed timing and delivery semantics carried by the M5 source experiment. The contamination AR(1) process advances on estimator cycle indices, independent of elapsed time and acquisition omissions. M6 therefore keeps timing assumptions, source acquisition, generated dropout, and range contamination distinguishable in saved configuration and source records.

## Paired benchmarks

A paired benchmark sweeps one of these factors: NLOS onset probability, NLOS magnitude, burst duration, equal per-beacon offset, correlated-noise standard deviation, adjacent-cycle correlation, quantization step, dropout probability, or base M5 range-noise standard deviation. Factor values must be distinct finite values and are stored with each entry.

For each factor value and seed, the service generates one experiment and fits the explicitly labeled estimator variants against the same saved observations. Within an initialization group, it reuses compatible physical starts from the first variant when possible and records the reference entry and any pairing failure. Variants may change the loss and its decision settings, solver, height coordinate, and evaluation budget; they share the physical model, priors, and initialization policy. Each entry stores all starts, including failed, nonconverged, or pairing-failed outcomes. Aggregates retain attempt denominators, counts of convergence and geometric accuracy, and distributions for available metrics; unavailable metric values are omitted from finite-value distributions and their counts are reported.

Application limits are 1–10 distinct factor values, 1–10 distinct unsigned 32-bit seeds, 1–4 labeled variants, no more than 40 benchmark runs, and no more than 240 total starts. Each run allows at most 12 starts and 5,000 function evaluations per start. These are workload limits, not statistical guarantees. Do not interpret a short seed list as a broad estimate of population variability.

## Saved data, reopen, and export

The browser uses `POST /api/m6/runs` for a saved run job and `POST /api/m6/sweeps` for a paired benchmark job. Both return a job ID; the UI polls the shared job endpoint and then opens the saved schema-6 result. Runs appear in generic `/api/runs` history and reopen through `/api/runs/{id}`. Benchmark history is listed by `GET /api/m6/sweeps` and reopened through `GET /api/m6/sweeps/{id}`. A server-side benchmark CSV is available at `/api/m6/sweeps/{id}/csv`.

`POST /api/m6/import` accepts a saved version-6 run or `robust_sweep` artifact. Import validates the existing records and deterministic source replay; it does not regenerate observations or solve the experiment. Run JSON export preserves the complete run record. Run CSV contains per-observation source rows, estimator decisions, labels, dropped-ping status and attempt status/messages; an empty acquisition exports an attempt-only placeholder. Benchmark Attempts CSV retains the complete backend start table plus solver messages; its separate Observations CSV retains source/decision rows across attempts, including failed attempts with no fitted decisions. Plotly PNG actions export the selected scene, signed-residual/decision chart, coverage chart, or paired benchmark chart as applicable. The main viewer continues to own the shared camera, coordinate alignment, comparison, ping scrubbing, and playback behavior.

Running jobs checkpoint JSON results so completed attempts remain available after interruption when the saved file is readable. A final storage failure can prevent a result from being persisted; checkpointing is not a guarantee against permanent write failure. Reopening an interrupted benchmark preserves completed entries and does not implicitly rerun missing entries. Imported and reopened results are viewed from their stored data.


### Viewer and recovery boundaries

M6 has independent solver, height-coordinate and initialization controls; geometry, path, timing, priors, starts and evaluation budget come from M4/M3 shared controls. Reopening restores contamination type, explicit seed and the complete offset vector, independently of which beacons receive NLOS. An offset vector is never masked by the NLOS beacon selection.

Main-scene rays sample at most 45 observations. Gray means weight at least 0.999, amber means positive weight below 0.999, and red means zero-weight rejection. Fixed-size markers locate affected pings; thick colored segments are the trajectory knots supporting those pings. The decision chart instead uses the configured flag threshold: teal unflagged, amber flagged, red rejected. Marker diameter is `4 + 6*(1-weight)` pixels. Injected labels never determine those colors. All observations remain inspectable in the table/CSV.

The numerical model preserves original actual, assumed and delivery timestamps. Assumed timestamps enter fitting; delivery latency does not change batch range geometry. AR correlation is indexed by acquisition cycle and does not model a continuous-time process. Interpolation/model projection, grouped-timing approximation and contamination remain separately reported.

A sweep checkpoints after each completed run, preserving the completed prefix. A single run saves its accepted request before fitting and its outcomes when the wrapper completes; termination during an optimizer does not save the optimizer's internal state. Restarted pending requests are disclosed as interrupted, without implicit solving. The latest terminal job outcome remains inspectable in memory if disk writes fail while the server lives. Temporary sweep recovery requires readable main JSON. No permanent-write-failure durability guarantee is made.
