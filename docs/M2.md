# M2: controlled sweeps and saved-run comparisons

M2 provides reproducible custom paths, bounded one-factor sweeps, and comparisons of two saved M1 run envelopes. The artifact implementation is in `uwb/experiments.py` and `uwb/sweeps.py`; the local UI is `web/m2.js` and the corresponding M2 section in `web/index.html`.

## Paths and motion

An experiment configuration may include `path`, overriding the reference scenario's trajectory. Path types are `line`, `circle`, `arc`, `rectangle`, `figure_eight`, and `waypoint`. Shared controls are `center_m` (default `[5,4]` m), `scale` (1), and `rotation_deg` (0). Shapes use `size_m` (default `[7,5.6]` m, or `[7,7]` for circle/arc); line uses only its width as length, while circle and arc require equal dimensions interpreted as diameter. Circle/arc start angle defaults to 0 degrees; arc sweep defaults to 180 degrees. Waypoints default to `[[-3.5,-2.8],[3.5,-2.8],[3.5,2.8],[-3.5,2.8]]` and are local xy offsets before scale, rotation, and translation. The UI exposes these shape, center, size, scale, rotation, arc-angle, and waypoint controls, along with samples and duration.

Custom-path bounds are: scale and each size dimension 0.01–100; center coordinates and waypoint coordinates −1000–1000 m; rotation and circle/arc start angle −360–360 degrees; arc sweep −360–360 degrees with magnitude at least 0.01; 2–100 waypoint pairs; 8–100 samples; and duration 0.01–3600 s. A waypoint path must have positive total length. Samples are equally spaced by traveled arclength, with both endpoints included, so the generated motion has constant speed over the configured duration. Piecewise-linear paths are interpolated by distance; circle and arc lengths are analytic; figure-eight arclength uses a fixed 16,385-point polyline approximation. The viewer joins fitted samples with straight display chords: those chords are not the continuous generating path. `path_metadata` records length, speed, sample spacing, parameterization, and this display convention.

## Sweep configuration and pairing

`validate_sweep_config` and `run_sweep` in `uwb/sweeps.py` accept one factor at a time:

| Factor | Meaning and bounds |
| --- | --- |
| `noise_std_m` | Injected range-noise standard deviation, 0–100 m |
| `path_scale` | Custom path scale, 0.01–100 |
| `samples` | Epoch count, integer 8–100 |
| `initial_error_m` | Truth-near Gaussian parameter initialization SD, 0–100 m |
| `assumed_std_m` | Assumed measurement sigma, 1e-6–1000 m |

Values must be finite and distinct (1–10 values). Seeds must be distinct unsigned 32-bit integers (1–10). Defaults in the API are factor `noise_std_m`, values `[0,0.05,0.1]`, seeds `[7,8]`, joint/independent fitting, two starts, initialization seed 19, and `max_nfev=1000`. API default variants are labeled budgets 200 and 1000. The UI supplies the current M1 experiment controls as its base experiment and the selected M1 mode, initialization, start count, and initialization seed; its factor and seed fields initially show noise values `0,0.02,0.05` and seeds `7,8`. Its paired-budget choice uses 200/2000 evaluations; the other choice uses one variant with 2000 evaluations. Variants can change only mode and/or evaluation budget.

The bounds are 40 runs, 12 starts per run, and 240 total starts. `path_scale` requires a custom path except for the `informative` and `nearly_collinear` reference scenarios, where it is converted to the default custom rectangle. The `initial_error_m` factor selects `truth_near` initialization automatically. Each value/seed cell gets one generated experiment. Variants within that cell reuse identical observations and trajectory starts; variants of the same mode also reuse beacon starts. For `known_map`, starts are projected onto the explicitly supplied synthetic truth map. Noise levels reuse the same seed's standard-normal draws; changing sample count creates a different epoch grid. Thus pairing is within each value/seed cell and does not imply identical data across different factor values. Truth-near initialization is diagnostic, not truth-independent recovery evidence.

The effective initialization stream seed is `(options.seed + measurement_seed) % 2**32`, recorded in every run. Independent initialization is data-dependent: its range-scaled guesses may change across factor levels, while variants within each value/seed cell use the same saved guesses. Truth-near perturbations enforce positive constrained coordinates at twice the solver floor (2e-6 m); the configured error is parameter SD rather than achieved geometric RMS error.

The UI's sample count and duration jointly control density: `(samples-1)/duration_s` epochs per second, including both endpoints. Ordinary application runs enforce duration 0.01–3600 s, noise 0–100 m, assumed sigma 1e-6–1000 m, 1–12 starts and 1–5000 objective evaluations per start. The standalone legacy generator retains its earlier finite-positive duration rules. GUI noise/uncertainty controls are global; saved observations retain per-beacon vectors.

## Outcomes, thresholds, and aggregation

Every attempted run and start, including failures and nonconverged estimates, remains in the version 2.0 sweep artifact. Its `start_table` classifies a missing estimate as `failed`, an unconverged optimizer as `not_converged`, a converged start meeting both geometry and residual criteria as `accepted`, and other converged starts as `converged_outside_thresholds`. The thresholds are saved with the artifact:

| Criterion | Exact (all injected noise levels are zero) | Noisy |
| --- | --- | --- |
| Geometry | Raw canonical/surveyed maximum tag-position and beacon error each ≤ 1e-5 m | Maximum tag-position and beacon error each ≤ 0.25 m; joint fits use proper rigid aligned errors and known-map fits remain surveyed-frame |
| Low residual | Maximum absolute range residual ≤ 1e-7 m | RMS normalized residual ≤ 2 |

`accepted` requires optimizer convergence plus both applicable geometry and residual criteria. These are disclosed descriptive thresholds; they do not follow from rank and do not establish uniqueness. Exact geometry uses raw coordinates, avoiding alignment concealing a canonical-frame difference. Noisy joint geometry is aligned by a proper planar rigid transform; scale is fixed at one and reflections are forbidden.

Aggregate failure rate uses all attempted starts as its denominator, including starts with no estimate. Failed-run count is also reported per value/variant. Geometry-error distributions include all finite estimates, even nonconverged ones; selected-start distributions use only each seed's selected start. The artifact also reports rank-deficient starts, accepted starts, runtime and error distributions, and per-entry solution-group counts. Grouping greedily compares each finite estimate to representatives using proper planar rigid aligned RMS over all trajectory and beacon xyz coordinates, threshold 1e-3 m. Low-residual groups use the applicable residual criterion above. Groups are descriptive sampled-start variability for one entry/data cell; there is no cross-seed grouping or exhaustive search, so counts are not a count of all mathematically unique solutions.

## Comparisons, persistence, and exports

`build_comparison(left_run, right_run, alignment='aligned')` accepts two saved run envelopes and performs no solves. `raw` preserves coordinates. `aligned` applies each run's saved evaluation alignment to its fit relative to that run's truth, using a proper planar rigid map-to-truth transform with scale exactly one and reflections forbidden. The comparison records shared metre bounds/equal scene scale, both runs' original fitted samples, and an elapsed-time reference reset to each run's first fitted epoch. It uses the union of elapsed epoch times for its piecewise-linear rendering data, without extrapolation or time warping; displayed comparison statistics use the original fitted samples. The UI shows both runs in a common 3D scene/camera and plots matched-epoch position error against elapsed seconds. Interpolation points are for rendering, not extra estimates.

The local service accepts `POST /api/sweeps` and `POST /api/comparisons`, lists saved artifacts at `GET /api/sweeps` and `GET /api/comparisons`, and reopens them at `GET /api/sweeps/<id>` and `GET /api/comparisons/<id>`. Sweep artifacts live under `runs/artifacts/`; each sweep run is also retained as an ordinary saved run under `runs/`, allowing selection in later comparisons. Artifact save/load validates strict JSON and recomputes aggregate/comparison tables from retained source data without solving or regenerating observations. The UI can reopen saved sweeps and comparisons after reload. It exports full sweep/comparison JSON, sweep CSV, comparison scene/chart PNG, and sweep chart PNG; the experiment-config control exports the current experiment controls as JSON. `table_csv(artifact)` in the API provides a table export with one row per start for a sweep or per run for a comparison.

Progress checkpoints contain every completed attempt. Stable server-owned run IDs prevent duplicate writes and imported artifacts from overwriting unrelated history. Atomic writes retry transient Windows reader locks; permanent failures retain the latest snapshot in the job and a complete temporary recovery file. A stopped/restarted partial sweep is disclosed as interrupted and does not resume implicitly. The comparison camera is shared by the overlay and preserved during in-page redraws; a fresh browser page starts with its default camera. JSON exports retain all fitted samples and interpolation data, including unavailable geometry as null.
